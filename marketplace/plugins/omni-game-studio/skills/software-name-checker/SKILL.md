# 软件名称查重 · Phase 0.5 前置锁死环节

名字定错，源程序文档、说明书、申请表全部重做。这是全流程唯一「越晚发现越贵」的环节：材料做好再改名等于整套重做，已下证再改名要重新申请。名称没锁死，不许进 Phase 1。

## 一句话事实（每次都要说清，不许顺着错误前提讲）

中国版权保护中心的软著登记是**形式审查**，**不比对名称是否已被他人登记**。别人已登记同名软著，证书照样发；同名软件过多，少数情况被要求补正说明，只是周期拉长。

所以查名称**不是为过审**，是为了避免「花几千块拿到证书，产品却不能叫这个名字」。真正的墙在**商标第 9 / 42 类注册**和**应用商店与小程序上架校验**。

两条不能错的表述：

- 不要说「名字被占用软著就办不下来」——同名照样下证，卡你的是商标和上架。
- 不要说「搜不到就是没被占用」——网页检索只是初筛，最终以官方数据库为准，且要截图留档。

## 名称锁死契约

1. Phase 0.5 结论落定后，软件全称与版本号进入**锁死**状态，全流程一字不改。
2. 三处逐字一致：源程序文档页眉、说明书封面、申请表「软件全称」三处必须是同一个「软件全称 + 版本号」。
3. 中途改名等于整套材料重做；已下证的改名等于重新申请。
4. 锁死后，主理人每次向成员下发任务都用同一全称，不得简写、不得换简称、不得加后缀。

## 主理人必须守住的三种判断

| 结论 | 主理人动作 |
|---|---|
| 必须改名 | **停下**，改完并重新跑完 Phase 0.5 才许进 Phase 1，不许带高风险名称往下做 |
| 建议微调，用户坚持不改 | 可以继续，但必须在最终交付（汇编四件套）里**保留这条风险原文**，不许抹掉 |
| 可以直用 | 立即锁死全称，之后所有下发任务复用同一全称 |

## 13 项命名合规规则（静态预检，逐条输出通过 / 不通过）

编号与判定由 `scripts/copyright_name_check.py` 定义，脚本逐条打印三态之一：通过、不通过（建议微调）、不通过（必须改名）。13 条全通过且六个渠道无命中，才可判「可以直用」。

| 编号 | 规则 | 不通过时的处置 |
|---|---|---|
| N01 | 全称长度 4–30 字（不含版本号） | 越界 → 建议微调 |
| N02 | 必须含品类词（系统 / 平台 / 软件 / 游戏 / 引擎 / 工具 / 小程序 / SDK 等） | 缺失 → 建议微调 |
| N03 | 敏感禁用字样（中国 / 国家 / 中华 / 全国 / 国际 / 世界 / 政府 / 官方 / 军用 / 中央 等） | 命中 → 必须改名，形审会直接补正或驳回 |
| N04 | 绝对化用语（第一 / 唯一 / 最好 / 最强 / 顶级 / 首创 / 极品 / 最高级 等） | 命中 → 必须改名 |
| N05 | 他人品牌词（知名游戏、引擎、平台、公司字号） | 命中 → 必须改名 |
| N06 | 开源项目名 | 命中 → 必须改名 |
| N07 | 开发残留词（demo / test / temp / 示例 / 新建 / 副本 / 占位 / untitled 等） | 命中 → 必须改名 |
| N08 | 纯通用词堆叠（智能 / 智慧 / 云 / 数据 / 管理 / 综合 / 通用 等加品类词，无独创词） | 命中 → 建议微调，独创性不足 |
| N09 | 地名与人名（行政区划名、常见自然人姓名） | 命中 → 建议微调，易被误认地域官方项目 |
| N10 | 中文字符占比不低于 0.30 | 偏低 → 建议微调 |
| N11 | 特殊字符规范（只允许中文、英文字母、数字、空格、连字符、点、间隔号） | 命中 emoji / 全角符号 / 引号 / 控制字符 → 必须改名 |
| N12 | 版本号格式（V 大写加数字，如 V1.0；版本串不得混进全称） | 不规范或混入全称 → 建议微调 |
| N13 | 与行业通用名重合度（用 --industry 传入行业词，独创词与行业通用名重合过高即判不通过） | 重合过高 → 建议微调 |

### 独创性启发式评分

脚本另给 0–100 分，由独创词长度、是否含非通用组合、通用词占比、品牌词命中、与行业通用名重合度共同加减分。

- 不低于 75 分：强，结构好看、不像通用词
- 50–74 分：中
- 低于 50 分：弱，追加一条「建议微调」

**高分只代表名字结构好看，绝对不代表能注册。** 脚本会给「磐石 + 行业词」打高分，但它不知道「磐石」在商标第 9 类早有多家注册。给候选名时必须把这句话说出来，否则用户会以为高分就是安全。

## 六个渠道占用核查（人工，脚本做不了）

脚本无法直连中国版权保护中心登记库和国家知识产权局商标库，两个系统都要登录加图形验证码。这六栏由主理人用联网检索逐条跑一遍，加引号做精确匹配，用报告里的「独创词」搜比全称命中率高。

| # | 渠道 | 检索式 | 命中意味着 |
|---|---|---|---|
| 1 | 软著登记公告 | `"{全称}" 软件著作权 登记` | 有人已登记同名，可继续，保留你的开发时间证据 |
| 2 | 商标第 9 / 42 类 | `"{全称}" 商标 第9类 计算机软件` 与 `"{全称}" 商标 第42类 软件设计开发` | 同名已注册 → 必须改名；申请中风险低于已注册；近似拿不准就建议咨询商标代理人 |
| 3 | 应用商店 | `"{全称}" app 下载` 与 `"{全称}" 小程序` | 同名在架 → 上架被拒，你要上架则建议改名；小程序名称唯一性校验更严 |
| 4 | 备案 | `"{全称}" 备案` | 一般记录即可，同行业知名则升为建议微调 |
| 5 | 企业 | `"{全称}" 有限公司` | 同名公司一般记录即可，同行业知名则升为建议微调 |
| 6 | 官网与产品 | `"{全称}" 官网` | 已有同类产品在运营 → 建议微调 |

看到同名但不同行业的，要判断商品类别是否构成冲突，别一刀切判死。第三方平台转载的登记信息能搜到登记号是确证，搜不到只是未发现，不能证明没登记。

## 三档结论（只有这三种，不许和稀泥）

| 核查结果 | 判定 | 处置 |
|---|---|---|
| N03 / N04 / N05 / N06 / N07 / N11 任一不通过 | 必须改名 | 停下，给备选名，改完重跑 Phase 0.5 |
| 商标第 9 或 42 类已有相同注册 | 必须改名 | 说清「不改的后果是被投诉下架」，不是软著过不了 |
| 商标近似注册、应用商店同名在架、N01 N02 N08 N09 N10 N12 N13 不通过、独创性偏弱 | 建议微调 | 用户坚持不改可继续，最终交付保留风险原文 |
| 软著已有同名登记 | 可以直用 | 保留开发时间证据，申请时不必主动说明 |
| 六个渠道全无命中且 13 项全通过 | 可以直用 | 仍提示以官方数据库为准、截图留档 |

一句话结论必须是：**可以直用 / 建议微调 / 必须改名**。不许写「可能存在一定风险，建议关注」。

## 需改名时给 3–5 个备选名

- 从脚本结果里挑 3–5 个，不要一次给 20 个让用户选花眼。
- 挑的时候看业务贴合度：「星轨塔防」比「苍穹塔防」更适合关卡制塔防，这种判断脚本做不了，要人来做。
- 明确推荐其中一个，说明推荐理由（业务贴合、常见字、好读好传播）。
- 不推荐纯生僻字组合，读不出、传不开，拿去注册商标也会被驳。
- 明确告诉用户：这几个名字**还没查过商标**，选定一个后回来再跑一遍六个渠道。

## W6 只查名称路由

只给结论，不自动改名、不顺手做材料。用户没让改就不要改，用户没让做材料就不要生成任何文件。查完把三档结论、六渠道表和备选名（如需）交回编排，由 `skills/copyright-filing/SKILL.md` 决定是否锁死并进入下一阶段。

## 脚本用法

```bash
python scripts/copyright_name_check.py --name "星轨塔防游戏软件" --version V1.0 --industry 游戏 --owner "某某工作室" --app-store 计划上架
python scripts/copyright_name_check.py --name "智能巡检管理系统" --version V1.0 --json
python scripts/copyright_name_check.py --help
```

脚本明确声明：静态预检不替代商标、应用商店、软著登记公告的人工核查，六个渠道需人工复核。

## 核查边界

本技能给的是命名合规与占用初筛，不是商标法律意见。商标近似判断最终以商标局审查为准，争议情形建议找商标代理人。正式提交前到 sbj.cnipa.gov.cn 做商标近似查询、到 ccopyright.com.cn 查登记公告，截图留档。词库会过时，发现明显漏判补进脚本词库即可。名称一旦定下并进入材料生成，三处逐字一致，中途改名等于重做。
