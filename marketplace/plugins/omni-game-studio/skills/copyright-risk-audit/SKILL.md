# 风险体检 · Phase 2 A 线

审查员不查代码是否原创、不比对相似度，所以「会不会被驳回」和「这证书有没有用」是两个不同的问题，必须分开回答。本线只做一件事：提交前把可能出问题的地方全部找出来，给一个不含糊的结论。

## 先分清两种风险

| 问题 | 属于 | 判定口径 |
|---|---|---|
| 材料能不能过形式审查 | 材料问题 | 三处一致、页数行数、待补项、日期逻辑、身份材料 |
| 证书将来能不能维权 | 真实性问题 | 权属、代码来源、AI 痕迹、过程证据 |

软著登记是**形式审查**，中国版权保护中心不比对名称是否已被他人登记、不检测 AI。AI 痕迹不影响过审，影响的是维权时的独创性主张强度——如实说，别吓人，也别隐瞒 AI 辅助。

## 12 项风险判定（逐项给依据、分级、规避动作）

现场证据要落到文件与行号，说「有密钥风险」是空话，说「源程序第 12 行硬编码了 AK」才是结论。

| 编号 | 风险项 | 现场判定依据 | 分级 | 具体规避动作 |
|---|---|---|---|---|
| R1 | 名称占用与商标冲突 | 六渠道检索结果、商标第 9 / 42 类注册状态、应用商店在架情况 | 同名商标已注册 🔴；近似注册、应用商店同名、软著同名登记 🟡；六渠道无命中 🟢 | 🔴 必须改名并停下重查；🟡 可继续但最终交付保留风险原文；证书照发，卡你的是上架 |
| R2 | 权属是否清晰 | 劳动合同、委托开发合同、合作开发协议、任务下达书 | 无合同且开发方式不明 🔴；外包无书面归属条款 🟡；有劳动关系或书面约定 🟢 | 补权属说明或书面约定；按条例第 13 条职务作品著作权归单位；结论交用户或律师定 |
| R3 | 开源许可证传染性 | 依赖目录、LICENSE 文件、SPDX 头、许可声明 | 源程序混入 GPL / AGPL 等强传染性代码 🔴；弱传染或允许性许可未署名 🟡；无第三方依赖 🟢 | 隔离或替换强传染代码，保留许可声明与署名，不得把别人代码当自己代码 |
| R4 | 密钥与真实数据泄露 | 硬编码 AK、私钥、数据库连接串、内网 IP、真实口令与真实业务数据 | 任一命中 🔴；全无 🟢 | 改环境变量读取，轮换已泄露密钥，剔除真实数据后重新生成源程序文档 |
| R5 | 日期逻辑是否自洽 | 开发完成日期、首次发表日期、申请日期及过程证据 | 编造日期或不满足 完成 ≤ 发表 ≤ 申请 🔴；发表状态未填、证据缺失 🟡；自洽且有 git 记录与构建日志 🟢 | 按真实过程证据更正，不编造；未发表就如实填未发表 |
| R6 | AI 痕迹是否过重 | 横幅注释、逐行复述注释、空壳 docstring、泛化命名、业务空洞 | 模板化明显、注释占比过高 🟡；有真实业务字段与异常分支 🟢 | 削注释到骨头、换业务命名、补脏数据处理；不影响过审，影响维权主张强度 |
| R7 | 是否踩代理陷阱 | 包过承诺、私人转账、加急包过、代签代填 | 已付款到私人账户或签包过协议 🔴；仅有口头承诺 🟡；官方渠道自助 🟢 | 只走官方渠道与对公账户，不承诺百分百过，不代签 |
| R8 | 第三方代码版权头 | Copyright、Licensed under、SPDX、All rights reserved 头 | 源程序文档含此类头 🔴；全无 🟢 | 剔除该文件后再生成源程序文档，脚手架与模板代码占比过高的另做替换 |
| R9 | 三处名称版本一致 | 源程序文档页眉、说明书封面、申请表「软件全称」 | 任一处不一致 🔴；三处逐字一致 🟢 | 整套重生成，不许局部改字；Phase 0.5 锁死后全流程一字不改 |
| R10 | 源程序页数与每页行数 | 页数标记、每页非空行数、是否取前 30 加后 30 | 缺文档、页码声明与实测页数不一致、或已达 60 页仍有页面不足 50 行 🔴；无页码标记待人工核对 🟡；60 页口径每页 50 行、或不足 60 页取全部 🟢 | 按 60 页口径重排；源码不足 60 页取全部，超过取前 30 页加后 30 页；不足 60 页时末页不足 50 行属正常，不判红 |
| R11 | 说明书待补项 | 待补充占位计数、真实界面截图数、章节数 | 说明书缺失或整篇占位 🔴；待补大于 0 或截图为 0 🟡；待补清零且每功能一张真实截图 🟢 | 显式清点并如实告知用户，不许抹掉；补齐后转 PDF |
| R12 | 身份证明材料 | 营业执照、身份证、著作权人与申请人一致性 | 材料缺失或与著作权人不符 🔴；复印件未盖章 🟡；齐全一致且盖章 🟢 | 补齐并盖章，核对著作权人全称与申请表逐字一致 |

## 分级标准

| 等级 | 含义 | 处理 |
|---|---|---|
| 🔴 高危 | 可能驳回、证书被撤销、造成实际损失 | 不解决不能交 |
| 🟡 中危 | 补正、周期拉长、效力削弱 | 能交但建议先改，或列进待补清单 |
| 🟢 低危 | 观感与专业度问题 | 记录，不影响提交 |

## 结论（只有这三种，不许和稀泥）

- **不能交**：任一 🔴 存在。列出全部高危项与现场证据。
- **补什么再交**：无 🔴 但有 🟡。逐条列出待补项、缺几处、补哪个文件，不许写成「建议关注」。
- **能交**：12 项全 🟢。仍提示以官方数据库为准、截图留档。

先说结论再给理由。结论不许写「可能存在一定风险，建议关注」，也不许承诺百分百过。

## 红线原文（交主理人原样进汇编交付，一条不许省略）

以下六条是固定红线原文，逐字复制进汇编交付的「红线」区；本轮自评表凡是判 🔴 的项，还要把该行「现场证据 + 怎么改」原文追加进去，一条不许省略、不许摘要、不许改成「建议关注」。

RED-01 源程序文档含云密钥、私钥、数据库连接串或硬编码口令：不能交，先改为环境变量读取并轮换已泄露密钥，再重新生成源程序文档。
RED-02 源程序文档含第三方版权头（Copyright / Licensed under / SPDX）或整段第三方代码：不能交，剔除该文件后再生成源程序文档。
RED-03 GPL / AGPL 等强传染性许可证代码混入自有源程序：不能交，先做许可证隔离与替换，不得把别人代码当自己代码提交。
RED-04 编造开发完成日期、首次发表日期或申请日期，或日期逻辑不自洽（完成 ≤ 发表 ≤ 申请）：不能交，按真实过程证据更正。
RED-05 三处（源程序文档页眉 / 说明书封面 / 申请表）软件全称与版本号未逐字一致：不能交，整套材料重生成，不许局部改字。
RED-06 名称查重判「必须改名」仍带高风险名称进入材料阶段：停下，改完并重新查重后才许进 Phase 1。

红线不让步的三条：密钥泄露、别人代码当自己代码、编造日期，必须明确阻止。

## 风险说人话（翻译示例）

| 术语 | 说给用户听 |
|---|---|
| 权属瑕疵 | 这软件法律上可能不算你的 |
| 商标冲突 | 证书能拿到，但你上架可能被打下来 |
| 强传染性开源许可 | 用了人家的代码，就得按人家的规矩来 |
| AI 痕迹过重 | 不影响过审，影响的是将来维权时你有多站得住脚 |
| 日期逻辑不自洽 | 三个日期对不上，审查员一眼就会问 |

## 提交前自评表

用 `templates/copyright/pre-submit-checklist.md` 落表：12 项，每项含红 / 黄 / 绿、判定依据、规避动作、状态栏四项；末尾两区分别是「结论：能交 / 不能交 / 补什么再交」与「红线清单（高危项原文，一条不许省略）」。状态栏允许留占位符，占位符只放在模板里，不进技能正文。

输出顺序固定：风险分级表 → 每条规避动作 → 提交前自评表 → 结论 → 红线原文 → 无法评估项。缺少劳动合同、委托合同、开发方式或是否已发表时，直接写「无法评估该项」，不靠猜。

## 脚本用法

```bash
python scripts/copyright_audit.py --root ./copyright-out --name "星轨塔防游戏软件" --version V1.0
python scripts/copyright_audit.py --root ./copyright-out --name "智能巡检管理系统" --version V1.0 --json
python scripts/copyright_audit.py --help
```

脚本给的是线索不是判决，每条命中都要人工看一眼。PDF 与二进制件无法可靠解析，脚本只做文本与 docx 的尽力筛查，解析不了的项标「需人工核对」而不是判绿。

源程序文档每页可能同时带页眉与页脚两处「第 X 页 / 共 Y 页」标记，脚本按页号分组、每页只计 1 次，标记行本身不计入正文行，保证实测页数与声明页数一致。不足 60 页取全部时末页不足 50 行属正常，判绿不判红。只有三种情形判红：超过 60 页未按前 30 加后 30 截取、页码声明与实测页数不一致、已达 60 页仍有页面不足 50 行。

## 边界

- 不替用户做法律判断：权属争议、侵权判断只给规则和后果，结论留给用户或律师。可以说「按条例第 13 条这属于职务作品，著作权归单位」，不能替用户拍板「这就是你的」。
- 权属信息不全、开发方式不明、是否已发表不明，必须停下来问清楚，不靠猜。
- 不夸大也不含糊，不承诺百分百过，不隐瞒 AI 辅助，重点是独创性和过程证据。
- 顺序不能反：名称没锁死不做材料，这是唯一「越晚发现越贵」的环节。
- 结论与红线原文交回 `skills/copyright-filing/SKILL.md` 汇编，成员之间不直连，跨成员信息流经主理人中转。
