# 软著材料生成套件

一句话定位：把「一个游戏项目目录」加工成「一套格式合规、能直接装进档案袋的软著材料」。本能力线只做材料，不做风险判决，不做流程讲解，不替用户判断权属。

## 0. 开工前置：名称必须先锁死

- 顺序不能反：名称没锁死不做材料。这是全流程唯一「越晚发现越贵」的环节。
- 前置阶段由 `skills/copyright-filing/SKILL.md` 编排。开工前须确认 Phase 0.5 名称查重结论已落定，且为「可以直用」，或「建议微调」且用户坚持不改（此时风险记录必须保留到最终交付）。
- 风控结论为「必须改名」时，本能力线一律停工，先改名再从头重跑，不许带高风险名称往下做。
- 上游未给出锁定结论时，不自行推断名称，直接回传「前置未完成」并停工。
- 名称与版本一旦写进页眉，三处逐字一致：源程序文档页眉、说明书封面、申请表「软件全称」的「软件全称 + 版本号」，一个字都不能差。中途改名等于整套材料重做，已下证的要重新申请。
- 不擅自改软件名称与版本号。用户给什么用什么，觉得不合规只提醒，改不改由主理人决定。
- 软著登记是形式审查，中国版权保护中心不比对名称是否已被他人登记。查名称的真正目的是避免「证书拿到手，产品却不能叫这个名字」——真正的墙在商标第 9 / 42 类和应用商店。
- 名称查重结论为「建议微调」且用户坚持不改时，材料清单与回传里必须保留该风险条目原文，不许在汇编时抹掉。

## 1. 四步链路

1. **扫描代码库**：遍历源码目录，识别语言构成、源文件数、有效代码行与功能模块；排除依赖与构建产物目录；同时初筛第三方版权头、疑似密钥、内网地址，形成项目画像。画像里的硬风险是待办清单，不是判决，每条都要人工看一眼。
2. **源程序文档**：按自然序摊平拼接源码，按 60 页口径分页，产出每页 50 行的分页文本，页眉写「软件全称 版本号」，页脚写连续页码。
3. **软件说明书**：按 `templates/copyright/material-templates.md` 第一节骨架逐节填写，功能章节与源码模块对应，预留截图位，填运行环境表；逐个清点占位处数，不许漏数。
4. **申请表与材料清单**：按同一模板第二、三节产出申请表填写信息稿与逐文件状态清单，复核分类推断、日期逻辑与三处名称版本一致性。

四步顺序不可跳步：前一步产物未通过验收，不进入下一步；未完成前置阶段不许跳到材料生成。

## 2. 产出物

| 文件 | 内容 | 是否需人工加工 |
|---|---|---|
| 项目画像 | 源程序量、文件数、语言构成、功能模块、硬风险清单 | 否，供后续步骤与验收消费 |
| 源程序文档（分页文本） | 60 页口径、每页 50 行、页眉页脚规范 | 是，须先清第三方代码与密钥，再转 PDF |
| 软件说明书 | 六章结构、功能与模块对应、截图位、运行环境表 | 是，占位处数须清零并补真实截图 |
| 申请表填写信息 | 逐字段口径、分类推断、日期逻辑、一致性核对 | 部分字段需确认 |
| 材料清单 | 每个文件带状态栏 | 否，但状态须如实标注并随进展更新 |

产出物一律放在同一个输出目录，便于逐字核对与整份作废重做。

交付口径分四段组织：能交了吗（一句话结论）、交什么（文件清单 + 每个文件状态）、怎么交（指向指导报告路径）、红线（高危项原文）。本能力线只产出「交什么」里的材料实体与状态栏，汇编结论由主理人统一给出，不越位代写。

## 3. 不可协商的口径

- **页数**：源码不足 60 页取全部；超过 60 页只取前 30 页 + 后 30 页，中间省略并在文首注明省略区间。采用哪一种口径要如实写进画像与清单，不许含糊。
- **行数与页眉**：每页正文固定 50 行，不低于 50；页眉居中写「软件全称 版本号」，页脚「第 N 页 / 共 M 页」且页码连续；页眉页脚是标记行，不计入 50 行正文。
- **拼接**：文件按自然序排列（mod2 在 mod10 前），每个文件前插入文件名分隔行；带第三方版权头的文件在该行就地标注，且不得纳入正文内容。
- **占位清点**：说明书里每一处 `【待补充】` 都要数出具体数量，如实回填材料清单与回传模板。不许抹掉，不许写「无」冒充完成，有多少处报多少处。
- **清洗**：带 `Copyright`、`Licensed under`、`SPDX-License-Identifier` 等第三方版权头的文件一律剔除；疑似密钥、内网 IP、真实数据先脱敏，已暴露的密钥必须轮换；依赖目录（`node_modules`、`vendor`、`third_party`、`Library`、`Temp` 等构建产物）一律不进源程序文档。脚本只报告风险，不改写源码。
- **三处一致**：申请表 / 源程序页眉 / 说明书封面逐字比对，作为验收硬项。
- **材料状态**：清单里每个文件只能标三种状态之一——可直接交 / 待补 X 处 / 需转 PDF。X 必须是具体数字，不许写「若干」。
- **页数自检**：按页眉切分生成物，数出实际页数与每页正文行数并写回画像；抽查第 1、30、31、末页。不许只看脚本终端输出就认定合格。

## 4. 可执行命令

```bash
python scripts/copyright_source_doc.py --help

python scripts/copyright_source_doc.py \
  --root ./src \
  --name "星轨塔防系统" \
  --version V1.0 \
  --out ./copyright-out/source-pages.txt \
  --pages 60 --lines-per-page 50 \
  --exclude Library --exclude Temp
```

只纳入指定语言、追加排除目录；名称改了以后整份重跑，不许只改页眉那一行文本：

```bash
python scripts/copyright_source_doc.py --root . --name "星轨塔防系统" --version V1.0 \
  --out ./copyright-out/source-pages.txt --ext .cs,.shader,.lua --exclude Library
```

示例名称仅示意，运行时一律用主理人锁定的软件全称与版本号。说明书与申请表按 `templates/copyright/material-templates.md` 三节骨架逐项填写，不需要额外脚本；占位符只存在于模板与生成出的草稿里。

脚本退出码：0 生成完成（风险线索写入文末报告）、1 参数或写入错误、2 未找到可纳入的源码行。脚本产出的是分页文本，不生成 PDF；文末会明确写出「需转 PDF 后提交」。

## 5. Phase 1 验收关卡（主理人执行，不合格退回重做）

主理人须在采信本能力线产出前逐项核对，任一不合格即退回本能力线重做，不得进入下一阶段：

1. **页数 / 行数**：抽查第 1、30、31 与末页，每页正文 50 行，页码连续，页眉「软件全称 版本号」无缺字、无错字。
2. **占位处数**：数出说明书占位的具体处数，与清单和回传模板里的数字一致；有未清的占位必须显式列出，不许报「已完成」。
3. **画像硬风险**：逐条列出第三方版权头文件数、疑似密钥处数、内网地址，并给出去除或脱敏动作；已暴露密钥须确认轮换。
4. **三处一致**：申请表、源程序页眉、说明书封面的名称与版本逐字比对。
5. **依赖排除**：确认源程序文档正文不含依赖目录或构建产物文件。
6. **格式状态**：清单中每个文件状态如实标注为可直接交 / 待补 X 处 / 需转 PDF。
7. **退回记录**：不合格项原文完整回传本能力线，不许摘要；重做后重新走完以上各项，不因「上次过了」而免检。

验收动作本身不改材料内容；退回时把不合格项原文完整回传，不许摘要。

## 6. 边界

- 不替用户判断权属。「这软件法律上可能不算你的」这类判断由申请人或律师确认，本能力线只把材料做对。
- 不承诺过审、不承诺百分百通过；软著是形式审查，但材料不合规照样补正。
- 不隐瞒 AI 辅助：重点是独创性与开发过程证据，源程序里不留模板化痕迹与占位内容。
- 源程序文档是分页文本，说明书同样需转 PDF 后提交；不假装已生成 PDF。
- 不代填在线表单，只提供可逐字段复制的填写信息稿。
- 所有跨成员信息流经主理人中转，本能力线不与其他成员直连，不采信未经主理人转交的结论。
- 不夸大也不含糊：风险说人话，例如「商标冲突」讲成「证书能拿到，但你上架可能被打下来」。
- 不接受「差不多 50 行」：不足 50 行的页要补齐或如实标注，不许用空行凑数充页。
- 不自行编造软件全称、版本号、著作权人；缺项时按主理人给定值填写并在清单里标为待确认。
- 政策与表单口径会变，正式提交前以官网当期要求为准，本能力线不冻结外部规则。

## 7. 工作流路由

本能力线对应 W1 全套申报中的材料段、W3 只做材料、W5 材料复核与修补、W7 名称改了重做材料。W7 时旧材料整份作废，页眉、封面、申请表三处全部重新生成，不许局部改字。W2 只做风险体检、W4 只要小白指导、W6 只查名称不属于本能力线，由 `skills/copyright-filing/SKILL.md` 路由到对应成员。

## 8. 回传给主理人的内容

- 产出路径、源程序量与文件数、语言构成、实际页数与截取口径、页眉文本
- 说明书占位处数与截图待补张数，逐条列出，不许报「无」
- 画像硬风险清单：第三方版权头文件、疑似密钥处数、内网地址，附去除动作
- 每个文件的状态栏，以及需转 PDF 的文件清单
- 三处名称版本比对结果
- W7 重做时旧材料的作废声明，以及新旧名称版本的差异记录
- 本次未通过的自检项与已采取的动作，不许只报「已完成」
- 跨线引用一律指向 `skills/copyright-filing/SKILL.md`，不引用其他成员尚未落盘的产物
