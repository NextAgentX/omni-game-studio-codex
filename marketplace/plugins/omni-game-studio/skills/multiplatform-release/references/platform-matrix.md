# 平台能力与约束矩阵

> ⚠️ **所有数值均为量级参考，会随平台政策变化。引用前必须以官方文档复核，并在交付物中标注复核时间与入口。**
>
> 本文件讲**平台侧**的约束，与引擎无关。**引擎侧**能否发到该平台、需要什么工具链，见 `engine-matrix.md` 的平台 × 引擎支持矩阵。下文构建步骤以 Cocos Creator 为例说明典型路径，Unity / Godot 的对应路径需按 engine-matrix 核实。

## 一、小游戏平台

### 微信小游戏

| 项目 | 说明 | 复核入口 |
|------|------|---------|
| 构建目标 | Cocos Creator 选择「微信小游戏」构建，产出含 game.js / game.json 的目录，用微信开发者工具打开 | Cocos Creator 官方文档「发布到微信小游戏」 |
| 主包体积 | 有严格上限（MB 级），首包超限无法提审 | 微信开放文档「小游戏 · 分包加载」 |
| 分包 | 支持分包加载，总包体有上限，单个分包也有上限；分包数量有上限 | 同上 |
| 远程资源 | 支持 CDN 远程加载，但需配置合法域名白名单 | 微信公众平台「开发设置 · 服务器域名」 |
| 音频 | 需用户交互后才能播放音频，BGM 启动时机必须设计 | 微信开放文档「小游戏 · 音频」 |
| 支付 | 虚拟支付有专门资质与规则，非普通微信支付 | 微信开放文档「小游戏 · 虚拟支付」 |
| 必备资质 | 主体资质、类目资质；含内购/广告变现时另有要求 | 微信公众平台类目与资质页 |

### 抖音小游戏

| 项目 | 说明 | 复核入口 |
|------|------|---------|
| 构建目标 | Cocos Creator 选择「抖音小游戏」构建（或通过字节小游戏构建插件），产出用抖音开发者工具打开 | Cocos Creator 官方文档「发布到抖音小游戏」 |
| 主包体积 | 有严格上限，与微信不完全一致，需单独核实 | 抖音开放平台「小游戏 · 包体与分包」 |
| 分包 | 支持分包，规则与微信存在差异（分包数量/大小） | 同上 |
| 广告 | 激励视频、插屏等广告能力通过抖音小游戏 SDK 接入 | 抖音开放平台「小游戏 · 广告」 |
| 入口差异 | 侧边栏、推荐流入口与微信不同，影响首屏设计与引导 | 抖音开放平台运营规范 |

**小游戏通用结论**：
- 首包是硬约束，架构阶段就要把「必须进首包的最小可玩集」定下来
- 所有超出首包的资源走分包或 CDN，且要设计加载时机（不能进游戏就全量下载）
- 引擎模块裁剪（未使用的 3D / 物理 / 粒子模块）通常是最容易拿到的体积收益

## 二、移动原生

### Android

| 项目 | 说明 |
|------|------|
| 构建目标 | 原生构建，产出 Gradle 工程，可打包 APK / AAB |
| 签名 | keystore 必须妥善保管且**每次发布保持一致**，丢失后无法覆盖更新 |
| 权限 | 最小化申请；隐私政策需与实际收集项一致 |
| 渠道 | 国内多渠道需渠道分包或统一接入渠道 SDK |
| 商店 | Google Play 需 AAB + 隐私清单 + 数据安全表单；国内各商店要求各异 |
| 风险 | 低端机 GPU 兼容（纹理压缩格式选择）、内存上限、后台被杀 |

### iOS

| 项目 | 说明 |
|------|------|
| 构建目标 | 原生构建，产出 Xcode 工程，需在 macOS 上编译签名 |
| 签名 | 证书 + Provisioning Profile，需与 Bundle ID 严格对应 |
| 审核 | 周期不固定；常见拒审：功能不完整、诱导评价、虚拟支付绕开 IAP、隐私说明缺失 |
| 支付 | 数字内容必须走 IAP，实物/服务可走第三方 |
| 隐私 | 需提供隐私清单（Privacy Manifest）与用途说明字符串 |
| 技术约束 | 不允许动态下发可执行代码（影响热更新方案设计）；JIT 受限 |
| 音频 | 静音开关行为需按 AVAudioSession 类别设计，否则"没声音"投诉高发 |

### HarmonyOS

| 项目 | 说明 |
|------|------|
| 构建目标 | 需使用支持鸿蒙的 Cocos Creator 版本（**版本相关，必须核实具体版本是否支持**） |
| 签名 | 与 Android 不同的签名与应用包体系，需按鸿蒙官方流程申请证书与 Profile |
| 上架 | 通过华为应用市场，流程与 Android 渠道不同 |
| 风险 | 引擎版本支持度是最大不确定性；设备覆盖与 GPU 差异需实机验证 |

## 三、桌面与 Web

### Windows

| 项目 | 说明 |
|------|------|
| 构建目标 | 原生构建，产出 exe + 资源目录 |
| 分发 | 可直接发 zip，或用安装包工具制作安装程序 |
| 风险 | 杀软误报（未签名 exe 高发）、显卡驱动兼容、路径含中文导致资源加载失败 |

### Web

| 项目 | 说明 |
|------|------|
| 构建目标 | Web Mobile / Web Desktop，产出 index.html + 资源 |
| 体积 | 无硬上限，但首次加载体积直接决定跳出率，通常按 MB 级控制 |
| 渲染 | WebGL 为主，WebGPU 视引擎版本与浏览器支持度而定 |
| 部署 | 需正确配置 MIME 类型与缓存策略；跨域资源需 CORS |
| 风险 | 移动端浏览器性能远低于原生、音频自动播放策略、iOS Safari 内存上限 |

### Linux

| 项目 | 说明 |
|------|------|
| 构建目标 | 原生构建（**支持度与引擎版本强相关，必须核实**） |
| 分发 | tar.gz 独立包、Steam、或各发行版打包格式 |
| 风险 | 依赖库版本（glibc、图形库）、发行版碎片化、Steam Runtime 兼容 |

## 四、跨平台共性检查

| 维度 | 检查点 |
|------|--------|
| 输入 | 触屏 / 鼠标 / 键盘 / 手柄的输入映射是否都覆盖 |
| 分辨率 | 安全区适配（刘海、手势条、小游戏胶囊按钮） |
| 性能档位 | 是否定义了高/中/低三档并绑定目标机型 |
| 资源格式 | 纹理压缩格式是否按平台分别配置（ASTC / ETC2 / PVRTC / DXT） |
| 存储 | 本地存储的键名与容量限制（小游戏 localStorage 有上限） |
| 时间 | 前后台切换、断线重连、时间跳变对计时逻辑的影响 |
